# 用户、登录与工作区

访问控制决定谁能进入实例、以何种方式登录、能看到哪些工作区与资源，以及管理员在异常时如何处理账号。先完成一个可恢复的管理员登录路径，再收紧注册和登录策略；不要在未验证 OAuth 或管理员密码前关闭唯一可用的入口。

## 用户生命周期

“用户”页面支持查看、创建和维护账号，并可进一步查看用户对话、知识库、记忆、登录历史和用量。管理员操作应遵循最小影响原则：

- **创建/修改账号**：确认邮箱归属、显示名、角色和初始密码。不要通过聊天、截图或工单发送明文密码。
- **提升管理员**：只对受信任人员授予。管理员可读取运营数据、修改渠道、导出配置和影响用户访问。
- **暂停或封禁**：适合安全事件、滥用或离职处理。先记录原因、时间和负责人，并验证用户的已有会话被正确终止。
- **重置密码或关闭 2FA**：先核验身份，操作后通知账号所有者并记录审计信息。
- **删除用户**：是影响数据的操作。先确认法律保留、工作区所有权、共享资料和备份策略；不要把删除当作“暂时禁用”。

定期检查登录历史、异常地区/IP、失败登录和高频注册。不要依赖单一指标判断攻击，而要结合邮箱、行为、用量和用户反馈处理。

## 注册与密码登录

“注册策略”中可控制是否开放注册、单 IP 注册限制、注册/登录验证码、邮箱验证、允许邮箱域名、密码登录和入口展示方式。

推荐的公共部署基线：

1. 初期关闭开放注册或启用严格的邮箱域名白名单。
2. 需要开放注册时，启用验证码、邮箱验证和合理的单 IP 限制。
3. 为管理员保留至少一个已验证的密码登录或身份源登录路径。
4. 在真实发布前，用非管理员测试账号走完注册、验证、登录、登出、刷新、重置密码和禁用后的行为。

密码登录可以与 OAuth 共存。若关闭密码登录、改为身份源选择器或自动跳转，系统会要求存在已启用的登录身份源；自动跳转还需要选择默认身份源。先在另一个浏览器或无痕窗口完成测试，再关闭原入口，防止把所有管理员锁在门外。

## OAuth、OIDC 与账号绑定

“登录身份源”支持 GitHub、Google、Apple、标准 OAuth2 与 OIDC。每个身份源应使用独立、受控的 Client ID、Client Secret 和精确回调地址。

上线一个身份源的安全步骤：

1. 先完成公开 HTTPS 域名和反向代理配置。
2. 在管理员后台创建身份源，复制后台给出的回调地址到服务商控制台。
3. 用测试账号发起登录，验证新用户创建、已有账号登录和显式账号绑定。
4. 检查邮箱匹配、自动创建、初始密码策略和用户组分配是否符合预期。
5. 再向真实用户开放入口或设置自动跳转。

启用自动创建账户前，要评估组织是否允许任何满足身份源条件的用户进入。若使用多个公开域名，配置固定 OAuth 回调域名和允许返回域名，详见[域名、HTTPS 与 OAuth](../deployment/domain-tls-oauth.mdx)。

第三方登录出现 `token_exchange_failed` 时，账号绑定正常并不意味着服务器出网也正常。应检查服务器到服务商 token endpoint 的 HTTPS、DNS、代理、防火墙、回调地址与系统时间，而不是反复解绑用户账号。

## 两步验证与会话安全

用户可以启用两步验证，管理员可在完成身份核验后协助关闭。两步验证不能替代：

- 强且唯一的管理员密码；
- 保护 `JWT_SECRET`、数据库密码和 OAuth Client Secret；
- HTTPS、正确 Cookie/反向代理配置和及时更新；
- 对被盗设备或离职人员及时封禁和会话撤销。

会话使用短期访问令牌与长期刷新令牌。降低访问令牌时长能缩短令牌泄露窗口；刷新令牌生命周期则应在用户便利和设备风险之间平衡。对多设备控制的完整策略应同时使用服务端会话记录、设备绑定、刷新令牌轮换、异常刷新检测、密码修改后的会话撤销和管理员封禁，而不是只缩短一个 TTL。

## 用户组、套餐与工作区

用户组用于把一组账号映射到模型可见性、额度、积分、套餐或运营规则。建议为管理员、内部员工、试用、付费和受限用户定义清晰、少量的组，不要创建难以追踪的例外组合。

工作区用于团队协作。创建和成员管理时确认：

- 谁是工作区所有者，离职或删除用户后如何转移归属。
- 成员能否创建、编辑、删除会话、项目、知识库和文件。
- 邀请链接是否有合理有效期、是否允许外部邮箱和是否应在使用后撤销。
- 将不同客户、法律实体或保密级别的数据放在独立工作区，不依赖用户口头约定隔离。

变更角色、用户组或工作区成员后，用一个低权限测试账号验证访问确实收紧或开放。不要只通过管理员视图判断权限。

## 安全运营检查表

- 至少保留两个独立、可恢复的管理员登录路径，并妥善保存恢复流程。
- 定期轮换 OAuth、SMTP、模型渠道和存储密钥；轮换后做真实登录与发送测试。
- 开启注册或自动创建前，明确允许的用户范围、邮件域名和滥用处理机制。
- 将用户、工作区、登录历史和敏感管理员操作纳入定期审阅。
- 删除、封禁、导出或恢复数据前，记录操作者、原因、范围和回滚方案。
