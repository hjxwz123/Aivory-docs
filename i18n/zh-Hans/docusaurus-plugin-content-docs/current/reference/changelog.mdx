# 更新日志

本页以 [GitHub Releases](https://github.com/hjxwz123/Aivory/releases) 的 tag 和发布时间为准。镜像部署请按对应版本说明固定镜像标签；`APP_IMAGE_TAG` 可单独固定应用版本，且优先于 `IMAGE_TAG`。升级前按[升级与备份](../deployment/upgrade-backup.mdx)完成备份。每个版本的完整提交范围、校验记录和原始说明仍以对应 GitHub Release 为准。

## v2.5.0-beta.3 — 测试版 — 2026-09-23

`v2.5.0-beta.3` 移除了 beta.2 加入的 AI PPT 创作台、管理配置、服务商接口和按份扣费。
统一产物面板、PPTX 文本编辑、文件夹上传以及对话生成文件预览继续可用。已有积分账本和
用量记录保留，供历史对账。详见
[GitHub 预发布说明](https://github.com/hjxwz123/Aivory/releases/tag/v2.5.0-beta.3)。

在 Compose 部署中固定此测试版本：

```dotenv
APP_IMAGE_TAG=2.5.0-beta.3
UPDATER_IMAGE_TAG=2.5.0-beta.3
```

## v2.5.0-beta.2 — 测试版 — 2026-09-22

此版本加入了对话生成文件预览，并修复了使用常规上传接口另存已编辑文档副本。完整历史
说明见 [GitHub 预发布说明](https://github.com/hjxwz123/Aivory/releases/tag/v2.5.0-beta.2)。

## v2.5.0-beta.1 — 测试版 — 2026-09-22

`v2.5.0-beta.1` 新增统一且可调整宽度的产物面板、文本/HTML/DOCX/XLSX/既有 PPTX 文本的
浏览器内编辑，以及面向沙盒任务的结构化文件夹上传。文件夹保留相对路径，暂存到
`/workspace/uploads/<folder>/<path>`，并向模型提供 `/workspace/aivory-uploads.txt` 清单。
初版 beta 会新增 `files.rel_path` 迁移列；回滚到旧版本时该新增列会保留。详见
[GitHub 预发布说明](https://github.com/hjxwz123/Aivory/releases/tag/v2.5.0-beta.1)。

## [v2.4.9](https://github.com/hjxwz123/Aivory/releases/tag/v2.4.9) — 正式版 — 2026-09-22

`v2.4.9` 将 2.4.9 各测试版的完成内容提升为正式版：用于工具路由、记忆、审核和文档选择的
TypeSafe/Jev 决策策略；更智能的工具路由和最多三次搜索的仅搜索模式；Tavily 搜索；域自动
加入与工作空间资料；公开 HTML 预览；企业微信登录；以及 Responses 消息 ID 修复。它是
2.4 系列推荐升级目标。TypeSafe 无需环境变量：渠道、凭据、模型和策略均保存在管理员配置
数据库中。

## v2.4.9-beta.1 — 测试版 — 2026-09-16

`v2.4.9-beta.1` 是用于测试的**预发布版本**，不是稳定生产版本。稳定版的应用内更新检查不会选择它。请先完成备份并在测试或预发环境使用；后续 beta 版本可能替代此版本。详见 [GitHub 预发布说明](https://github.com/hjxwz123/Aivory/releases/tag/v2.4.9-beta.1)。

- **仅搜索自动路由**：自动模式会把简单聚焦的 Web 搜索请求分到一次 Aivory 搜索批次，避免不必要的多轮工具调用。复杂调研、全文读取、文件、代码、图片、技能、记忆和自定义工具仍使用完整工具集。关闭模式不再无条件禁用所有工具，而是仅暴露已获准的 Aivory 搜索。
- **域管理**：一条规则可精确匹配最多 50 个域名，创建后默认启动自动加入。平台管理员可停止后续自动加入而不影响手动添加，可在 **域用户** 中添加或移除任意符合条件的成员，并让历史个人对话通过下载、获准的工作空间私有迁移或稍后从数据管理处理。
- **工作空间公告与工具选择器**：工作空间所有者和管理员可发布公告；编辑器控件已覆盖英文、简体中文、繁体中文、日文和法文。工具选择器不再显示模式解释文字。
- **图片参考**：支持的图片生成请求会包含当前轮上传的参考图片。

Docker 固定版本测试部署请使用精确的预发布标签：

```dotenv
APP_IMAGE_TAG=2.4.9-beta.1
UPDATER_IMAGE_TAG=2.4.9-beta.1
```

不要把该 tag 视作稳定自动更新。请先备份，验证域策略和个人数据迁移行为，并在后续经验证的版本可用后替换此 beta。

## v2.4 系列

### [v2.4.8](https://github.com/hjxwz123/Aivory/releases/tag/v2.4.8) - 2026-09-16

本版本集中完善工作空间管理、企业域注册规则与权限边界，新增工作空间公告、使用统计和管理员后台更新，支持生成图片的 Mask 局部编辑，并修复 Passkey 登录、个人对话批量清理、历史备份恢复和检索超时问题。

#### 工作空间管理、公告与统计

- 工作空间管理改为与用户设置一致的布局：桌面左侧分类导航、右侧内容；手机使用全屏弹窗和顶部横向导航。成员、邀请、能力、公告、审计、统计统一收纳，普通成员仍只查看有权访问的成员信息。
- 标题和底部操作保持可见，成员、邀请和审计列表共用正文滚动区域，避免嵌套滚动条；切换分类回到顶部，支持方向键及 Home / End 操作。
- 工作空间所有者和管理员可以发布仅本空间可见的公告，支持富文本、配图、弹窗、顶部通知栏、记住关闭状态和必读倒计时。工作空间公告与全站公告独立配置，更新会通知在线客户端并记录审计事件。
- 新增最近 24 小时、7 天、30 天、90 天和 365 天的使用统计，包含对话轮数、调用次数、输入／输出 Token、活跃成员、Credits、供应商成本、成员用量及上一周期对比。仅当前空间管理者可访问，统计权限不会授予查看其他成员私有对话正文的权限。
- 新增 `workspace_announcements` 表，启动时自动迁移；公告数据纳入完整备份，配图需同时备份文件。配置导出不包含公告数据行。

#### 用户组、工作空间与隐私对话权限

- 系统用户组、工作空间总开关、普通成员权限和资源访问规则共同生效；任一适用层拒绝时，对应操作不可用，工作空间允许不能覆盖用户组禁止。
- 工作空间所有者／管理员可以越过普通成员级限制，但仍受用户组和工作空间总开关约束；系统管理员保留用户组豁免，同时遵守工作空间总开关。
- 补齐 Prompt、Skill、删除工作空间、自建 MCP 服务、知识库内容操作、项目资料、附件转存和自动入库的权限校验；修复前端不识别 `usermcp:*` 通配授权的问题。
- 项目启用自动加入知识库前检查实际上传权限，权限收回后仍可关闭已有选项；工作空间关闭知识库时，获准上传的普通对话附件仍可上传，但不会自动入库。
- 系统用户组和工作空间均可控制隐私对话，两层都允许时才显示入口。企业域账号锁定个人空间不再无条件隐藏隐私对话；访客仍不能使用。
- 隐私请求由服务端重新检查指定空间、模型、图片上传权限和成员额度，并响应进行中的权限撤销。统计仅保留必要的空间归属，不持久化隐私对话正文。
- 添加域名时显示权限交集提示，建议默认用户组开放所需能力，再由工作空间按需收紧；添加／编辑域名弹窗修复嵌套滚动条，保存和取消按钮保持可见。

#### 企业邮箱域注册规则

- 平台管理员可以将精确邮箱域映射到工作空间，设置初始用户组、自动入组、密码注册邮箱验证和个人空间锁定；已有账号不会被追溯入组。
- 密码注册按全局设置与命中的有效域规则共同判断：任一要求验证时需要验证码，两处均关闭时可直接注册。第三方和通用 OAuth2 新账号同样遵循域入组、初始组和个人空间规则，不额外要求 Aivory 邮箱验证码。
- 账号、域绑定和空间成员关系在同一事务中创建。个人空间限制同时在前后端执行，管理员可设置用户级例外；暂停规则停止后续自动入组，删除规则解除绑定与限制并保留成员关系和数据。
- 支持平台管理员创建工作空间并指定负责人，以及从当前成员中更换负责人。`registration_domains` 与 `domain_users` 纳入迁移和备份。

#### 图片编辑、对话整理与项目操作

- 支持的 OpenAI 格式绘图模型生成图片后，可从编辑入口涂抹选中区域，提交原图、PNG Mask 和修改要求。编辑器支持画笔、橡皮擦、笔刷大小、撤销／重做、清空与选区预览。
- 编辑消息、重试和重新生成保留对应编辑参数；服务端检查图片与 Mask 的访问权限、会话／分支归属、格式和尺寸。优化绘图编辑器与正在绘制状态，适配小屏幕及减少动态效果的偏好。此功能要求上游支持图片编辑，DALL·E 3 不在支持范围内。
- 修复“清除全部对话”只能清除前端已加载部分的问题，改为服务端分批清理完整个人历史，包含已归档对话；新增“全部归档”，不依赖侧边栏分页，且不修改工作空间共享对话。
- 优化已归档对话弹窗的视口约束与滚动，移除不准确的“模拟”等文案。
- 侧边栏项目右侧改为与详情页一致的三个点操作菜单。删除项目时可勾选同时删除全部对话；未勾选则保留对话并移出项目，删除操作继续校验相关权限。

#### 登录、备份与检索修复

- 修复 Passkey 登录的 `Backup Eligible flag inconsistency detected during login validation`：持久化认证器备份资格／状态标记，旧凭据仅在签名、挑战、来源、RP ID 和身份验证通过后补齐缺失标记；已知凭据继续执行一致性检查。
- 登录挑战只累计真实验证失败，成功后一次性消费；改进来源错误提示、服务端诊断及账号页 Passkey 管理。
- 历史 v3 备份按兼容表结构和当前外键依赖顺序恢复，无效备份在修改数据前被拒绝。恢复时保留当前管理员有效 Passkey 和设备端 user handle，凭据冲突则回滚。
- 证据充分性判断单独超时、整体请求仍有效时，保留已完成的检索结果作为部分证据继续回答；请求取消、整体超时、计费失败或无有效证据仍返回错误。

#### 管理员后台更新与升级说明

- 管理员侧边栏增加版本标签，有新正式 Release 时突出显示；点击查看当前／最新版本、发布时间和完整更新日志，并可发起更新。长更新日志使用单一滚动区域。
- 内部 `updater` 服务先拉取目标版本、写入 `APP_IMAGE_TAG`，再仅重建 `app` 并等待健康检查；任务持久化，失败时尝试恢复旧应用镜像配置。此回退不等同于数据库恢复。
- 已配置更新器的部署可从后台更新；手动仅升级应用时，在原 `.env` 中设置 `APP_IMAGE_TAG=2.4.8`，再执行 `docker compose -f docker-compose.prod.yml pull app` 和 `docker compose -f docker-compose.prod.yml up -d --no-deps --no-build app`。
- 没有更新器的旧部署需先将新 Compose 的 `updater` 服务、`update-state` 卷和应用更新器环境变量合并到原配置，并设置 `UPDATER_IMAGE_TAG=2.4.8`；只拉取 `app` 不会自动创建更新器。保留原项目名、端口、数据路径、数据库密码和 JWT 密钥，不要执行 `down -v`。
- 应用、更新器、沙箱运行时和 sidecar 的版本镜像均以 `2.4.8` 为标签，支持 `linux/amd64` 与 `linux/arm64`。等所需镜像构建完成后再拉取；本次仅升级应用不要求同步更换沙箱。数据库迁移在启动时自动执行。
- 发布前通过 668 项前端测试、Go 全量测试、5 项更新器测试、类型检查与生产构建，并在五种视口下完成弹窗布局及交互检查。

完整升级命令和兼容性说明见 [v2.4.8 Release](https://github.com/hjxwz123/Aivory/releases/tag/v2.4.8)；完整提交范围见 [v2.4.7…v2.4.8](https://github.com/hjxwz123/Aivory/compare/v2.4.7...v2.4.8)。

### [v2.4.3](https://github.com/hjxwz123/Aivory/releases/tag/v2.4.3) - 2026-08-31

- 渠道配置现在支持逐个添加模型，也可以从上游模型接口获取列表后批量勾选导入；兼容 OpenAI 格式的 `/v2`、`/v3` 等自定义 API 根路径。
- 工具调用方式改为按对话生效：管理员设置新对话的默认值，用户只能在具体对话中临时修改，开启新对话后恢复管理员默认配置。
- 同一线性分支的并发发送会在服务端串行处理；被拒绝或中断的发送会自动完成状态同步。AI 回复期间可以排队一条带附件和完整选项的后续消息，回复结束后自动发送，也可以撤回到输入框。
- 新增只读沙盒文件抽屉，支持查看文件夹、进入目录、刷新列表和预览支持的文件；接口会校验会话权限、限制安全相对路径，并隔离沙盒内容的浏览器预览。
- 标题、任务、工具路由等内部模型调用会携带所选模型的 `extra_params`，标题和工具路由调用也有更充足的输出空间；未配置可用图片模型时，画图工具会显示为不可用。
- 备份导入增加完整性校验并改为原子恢复，同时改进聊天侧边栏、首页卡片、空菜单和回复状态提示。
- 数据库迁移会在启动时自动执行。固定 Docker 版本时，应用、沙盒运行时和 Sidecar 镜像全部发布后使用 `IMAGE_TAG=2.4.3`；本版本不新增必填环境变量。

### [v2.4.2](https://github.com/hjxwz123/Aivory/releases/tag/v2.4.2) - 2026-08-30

- 密码注册与 OAuth/OIDC 自动创建账号改为独立策略，可以关闭直接注册，仅允许用户通过启用的第三方身份源首次注册。
- 同一账号可以同时登录多台设备，并继续保留刷新令牌重放防护与安全状态校验；登录页同时增加由浏览器密码管理器托管的“记住密码”。
- 已禁用的模型或渠道不能再保存或用于模型策略、任务调用、工具路由与新对话执行。
- 管理员可以设置默认的“自动、开启、关闭”工具模式，仅当账号和当前消息都没有主动选择时生效。

- 使用域名或 HTTPS 部署时必须在 `ALLOWED_ORIGINS` 中填写浏览器实际 Origin；同源 IP/HTTP 测试可留空。本次没有数据库迁移，也没有新增必填变量。

### [v2.4.0](https://github.com/hjxwz123/Aivory/releases/tag/v2.4.0) - 2026-08-29

`v2.4.0` 将个人部署从“需要维护一组外部基础设施”的方案，扩展为可直接运行的单实例版本；同时继续保留并兼容原有的 PostgreSQL、Redis 与 Qdrant 完整部署。该版本也集中完善了管理员初始化、工具执行可靠性、认证会话安全、RAG 保护与聊天体验。

#### 个人部署与内嵌向量

- 新增 `deploy/docker-compose.personal.yml` 与 `.env.personal.example`。个人版使用 SQLite 保存业务数据和向量数据，并以进程内缓存、队列替代 Redis，不再要求单独部署 PostgreSQL、Redis 或 Qdrant。
- 向量后端新增 `VECTOR_BACKEND=sqlite`。个人版以精确余弦相似度检索内嵌向量，适合单机、低维护成本的个人使用；SQLite 向量数据会纳入逻辑备份流程。
- Python 沙盒在个人版中默认不随主服务启动。需要代码执行时，可通过 Compose 的 `sandbox` profile 选择性启用；未配置本地沙盒时，管理端会给出明确的配置提示。
- 原有完整部署的服务编排、环境变量和数据路径保持不变。个人版仅面向单实例运行，不支持横向扩展，也不应将 SQLite 数据库放在 NFS 等网络文件系统上。

#### 管理引导、渠道与模型配置

- 管理员首次进入后台会进入可逐页漫游的配置引导，而非静态检查清单。引导可跳过、可在之后重新打开，并可跳转至对应配置页面后重新检测状态。
- 引导会识别个人版和完整版：必要项涵盖渠道、聊天模型和默认模型；嵌入模型、搜索、沙盒与 SMTP 被作为按需启用的增强项展示。
- 渠道模型页支持从服务商模型接口发现并批量导入该渠道支持的模型。导入过程会明确反馈重复模型、不支持的模型、部分成功、空结果和请求失败，避免误以为配置已经生效。
- 管理概览新增近 24 小时活动、配置健康状态和全局离线指示；工作空间知识库信息可展开查看，便于排查资源与配置关联。

#### 工具执行与模型调用可靠性

- `aivory_web_search` 一次最多支持 5 个查询，`web_fetch` 一次最多支持 4 个 URL；系统会控制并发、去重并稳定排序，即使部分请求失败也会返回可用的部分结果。
- 为单轮工具调用增加次数、时间和进度预算，并检测重复调用或无进展循环。达到限制后会以不再调用工具的最终回答结束本轮，而不是继续无限重试。
- 该保护覆盖 OpenAI Chat、OpenAI Responses、Anthropic、Gemini、提示词工具流与 Deep Research 等调用路径；新增明确的 `tool_budget_exceeded` 与 `tool_no_progress` 错误状态，方便定位问题。
- 工具编排与上下文压缩逻辑完成拆分，并补充回归覆盖，降低多工具、长对话和流式响应交织时的异常风险。

#### 图片生成与编辑

- 图片流程会明确区分“生成新图片”和“基于附件编辑”。当一轮存在多张附件时，用户可以指定用于编辑的基础图片，其余图片仍作为参考保留。
- 不再将历史附件意外带入新的编辑请求；基础图片无法唯一确定时会安全地拒绝执行，而不是随机选取图片。
- 保持服务商参数、尺寸、生成数量、回退、额度和用量记录的一致性，并能安全处理已删除会话附件的历史引用。

#### 认证与会话安全

- 滑块验证码改为服务器签名的通行令牌，增加过期与重放防护，避免客户端状态被直接伪造或复用。
- GitHub 等 OAuth 身份源在交换令牌发生超时时，会使用新的连接重试；同时延长超时时间，并使用固定的公开错误白名单，改善网络波动下的登录失败体验。
- 登录启用独占刷新会话：同一账户在新设备登录后，旧设备刷新会话会失效。检测到 refresh token 重放时，会撤销整个会话族，防止泄露令牌被持续换取新访问令牌。
- 浏览器端使用 Web Locks 串行化多标签页刷新请求；刷新、会话查询和退出登录接口增加 CSRF 校验。

#### RAG、文档与托管工具安全

- 当嵌入模型或渠道仍被全局设置、知识库引用时，系统会阻止删除；向量身份信息同样不能在存在引用时修改，避免旧文档向量失去可检索性。
- 冲突场景显示可执行的本地化恢复说明，而不再直接暴露数据库外键错误。文档解析器与 MinerU 不可用时，也会在文档工作流中展示可理解的故障原因。
- 所有模型不再隐式附带服务商托管工具。需要使用 Hosted 工具时必须显式配置，避免 OpenAI 渠道或其他模型在管理员未知的情况下拥有默认工具权限。

#### 聊天、公式与界面体验

- 点击已渲染的行内或块级公式即可复制完整 LaTeX 源文本，并提供本地化的成功或失败反馈；此改动关联 [#25](https://github.com/hjxwz123/Aivory/issues/25) 并由 [#26](https://github.com/hjxwz123/Aivory/pull/26) 完成。
- 补全思考耗时展示和恢复后的计时行为，修复 Markdown 加粗标题的换行表现；移动端头像菜单与桌面端功能保持一致，图片附件在消息气泡内正确约束尺寸。
- 新对话会恢复已配置的默认工具选择。历史对话支持分享入口，重命名、字体、抽屉层级、侧边栏和文件页面的视觉层次经过统一，减少不必要的边框线。
- 桌面聊天顶部栏从 56px 收紧为 48px，减少对对话内容的遮挡；设置页标题字体与主对话标题对齐，抽屉引用文字也使用统一字体规则。

#### 权限、后台与沙盒恢复

- 用户组与工作空间成员权限增加会话删除控制，并分别校验会话删除与消息轮次删除，避免仅凭宽泛权限越界删除内容。
- 用量记录和管理员搜索支持昵称，后台排查用户行为更直接。
- 针对只读根文件系统下的运行环境完善沙盒归档恢复；改进产物链接识别，提升代码执行文件的访问可靠性。

#### 镜像与平台支持

- 应用、沙盒 runner 和 sidecar 镜像均发布 `linux/amd64` 与 `linux/arm64` 版本，且与应用使用相同的语义版本标签。Compose 会按主机架构自动选择正确镜像。
- 32 位 ARM 不在支持范围内。ARM64 与 AMD64 部署均应使用 `v2.4.0` 或后续的对应版本 tag，不要将不同组件固定到不一致的版本。

#### 升级说明

- 数据库迁移会自动执行，无需手工运行 SQL。使用 SQLite 向量时会创建 `vector_points` 表，并随常规数据库备份一起处理。
- 原有完整版部署不需要因个人版而迁移架构；个人版与完整版的 Compose 配置不能混合启动。升级前请确认实际部署模式，并遵循[升级与备份](../deployment/upgrade-backup.mdx)中的备份步骤。
- 独占会话策略可能使同一账户在其他设备被登出；这是预期的安全行为。升级后应复查 Hosted 工具的显式配置，以及仍被知识库引用的嵌入模型/渠道，先迁移引用再修改其向量身份。
- 本次不要求新增必填环境变量。完整部署和个人部署均可继续使用已有的版本化镜像策略。
