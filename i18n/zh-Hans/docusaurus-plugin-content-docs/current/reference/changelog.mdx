### [v2.5.0-beta.5](https://github.com/hjxwz123/Aivory/releases/tag/v2.5.0-beta.5) — 2026-09-25 — 预发布

#### Aivory v2.5.0-beta.5

> 测试版 / 预发布版。

此版本包含 PR #36 中的 AI PPT 工作台和分层权限，随后还加入了直接将文件夹上传到对话沙箱的功能。

##### AI PPT

- 使用 Aivory 自有的演示文稿工作流恢复 AI PPT，而非已停用的嵌入式供应商界面。浏览器使用 Aivory 端点；Docmee API 密钥和调用仍保留在服务器端。
- 使演示文稿界面与网站其余部分保持一致，包括大纲编辑、模板选择、演示文稿列表和预览。
- 管理员可以按用户组控制 AI PPT 访问权限。工作区管理员可以控制工作区策略和成员访问权限。只有所有适用层级都允许时，用户才拥有有效访问权限；访客不能使用 AI PPT。
- 生成和付费编辑继续使用 [AI PPT 指南](https://github.com/hjxwz123/Aivory/blob/v2.5.0-beta.5/docs/ai-ppt-docmee.md)中所述的积分和使用记录。

##### 文件夹上传

- 仅当已配置沙箱，且用户组和工作区均允许文件上传和沙箱工具时，才显示**上传文件夹**。
- 在一个请求中发送所选目录。在当前对话沙箱中，保留其原始字节和相对路径，并存放在 `/workspace/folders/<folder>/` 下。不会进行逐文件文档摄取、图像转换或 RAG 索引。
- 强制执行路径安全检查，并限制为每个文件夹最多 300 个文件、每个文件夹 200 MiB、每个文件 40 MiB。目录拖放不会被当作普通文件附件处理。
- 普通文件上传不变。如果沙箱写入过程中途失败，部分已写入文件可能会保留；界面会报告此情况。请参阅[文件夹上传指南](https://github.com/hjxwz123/Aivory/blob/v2.5.0-beta.5/docs/folder-upload.zh-CN.md)。

##### 验证

- 140 个前端测试文件中的 824 项测试通过。
- Go API、store 和 tools 测试通过；生产环境前端构建通过。
- 未运行截图测试。

##### 升级

这是一个测试版。部署前请备份数据库和应用数据。数据库迁移会在应用启动时运行。AI PPT 需要启用 Docmee 配置；文件夹上传需要配置沙箱。

应用、更新器和两个沙箱镜像发布完成后，将部署实际使用的 `deploy/.env` 设置为新的镜像标签：

```dotenv
IMAGE_TAG=2.5.0-beta.5
UPDATER_IMAGE_TAG=2.5.0-beta.5
```

移除或调整任何显式设置的 `APP_IMAGE_TAG` 或 `SANDBOX_IMAGE_TAG` 覆盖项，然后验证并部署：

```bash
cd deploy
docker compose --env-file .env -f docker-compose.prod.yml config --images
docker compose --env-file .env -f docker-compose.prod.yml pull
docker compose --env-file .env -f docker-compose.prod.yml up -d --no-build
```

### [v2.5.0-beta.4](https://github.com/hjxwz123/Aivory/releases/tag/v2.5.0-beta.4) — 2026-09-23 — 预发布

#### Aivory v2.5.0-beta.4

> 测试版 / 预发布版。

此版本为使用纯文本模型的对话增加了图像读取功能。管理员可以在 **设置 > 模型策略**下选择一个已启用且支持视觉的聊天模型。配置后，该模型会读取附加图像，并向所选对话模型提供结构化文本证据。原生支持视觉的模型仍会直接接收图像。将此设置留空时，纯文本模型仍会沿用现有的跳过图像行为。

在普通对话中，图像证据会与上传的文件一起缓存；当视觉模型或证据提示词版本发生变化时，会重新生成。每轮最多发起四次新的视觉调用；缓存的证据不受此限制，仍可使用。私聊不会存储图像缓存，且只读取最新用户轮次中的图像。如果图像读取失败，对话仍可在不使用无法读取的图像的情况下继续。

视觉读取会记录为 `task.vision_caption` 使用量，可能增加延迟和模型成本。此版本不会恢复 beta.3 中移除的 AI PPT 集成；普通 PPTX 预览和编辑仍可用。

##### 升级

应用和更新器镜像发布完成后，管理员可以在**系统更新**中选择 `v2.5.0-beta.4`。如需手动使用 Compose 更新，请使用：

```dotenv

UPDATER_IMAGE_TAG=2.5.0-beta.4
```

```bash
docker compose -f docker-compose.prod.yml pull app updater
docker compose -f docker-compose.prod.yml up -d --no-deps --force-recreate updater app
```

### [v2.5.0-beta.2](https://github.com/hjxwz123/Aivory/releases/tag/v2.5.0-beta.2) — 2026-09-22 — 预发布

#### Aivory v2.5.0-beta.2

> 测试版 / 预发布版。

`v2.5.0-beta.2` 新增了 Docmee / 文多多 AI PPT 工作台、保障积分安全的演示文稿计费，以及聊天中对生成文件的预览控件。

##### AI PPT 工作台

- 新增 **AI PPT** 页面和侧边栏入口，通过其 iframe SDK 嵌入 Docmee 演示文稿创建工具。
- 在 **管理 → 积分与配额 → AI PPT（文多多）** 中配置集成：启用开关、API 密钥、每份演示文稿的价格、创建器版本、令牌有效期、API 源站、SDK URL，以及可选的国际版或代理 URL。
- 将 Docmee API 密钥保存在服务器上。浏览器只会收到一个与用户关联的短时 iframe 令牌，上游错误不会泄露服务提供方详情。
- 支持中国默认源站、Docmee 国际版源站、管理员管理的代理，或自托管 SDK 脚本。

##### 积分与用量

- 在生成开始前预留配置的积分；Docmee 报告演示文稿已生成后结算一次扣费，并在适当情况下释放未使用的预留积分。
- 使用 Docmee 演示文稿 ID 作为幂等键。SDK 重试、页面重新加载和重复事件都不会对同一份演示文稿重复扣费。
- 当用户无法支付配置的价格时，阻止生成并显示明确的充值状态。平台积分或每份演示文稿价格关闭时，生成仍然免费。
- 在用量日志和用量统计中，以新的 `ppt` 用途记录已结算的 AI PPT 扣费，因此管理员计费和用量页面会显示实际扣除的积分。

##### 生成文件预览

- 在聊天中生成文件卡片的下载控件旁新增预览控件。
- 对 HTML、PDF、Word、PowerPoint、电子表格、文本和支持的图像文件，在现有的 Artifact Panel 中打开预览。
- 保留安全的 URL 处理和图像灯箱行为。当生成文件名没有可用扩展名时，MIME 类型回退机制可改善预览选择。

##### 发布修复

- 修复导致首个测试版受阻的文档副本上传客户端方法。预览编辑器现在使用现有的 `POST /api/files` 上传流程，将编辑后的文件保存为新的附件。
- 解决 beta.1 的兼容性修复与 PR #32 更完整的文档副本客户端方法之间的合并冲突。

### [v2.5.0-beta.1](https://github.com/hjxwz123/Aivory/releases/tag/v2.5.0-beta.1) — 2026-09-22 — 预发布

#### Aivory v2.5.0-beta.1

> 测试版发布 / 预发布版本。

`v2.5.0-beta.1` 引入了统一的可调整大小的产物面板、基于浏览器的文档编辑，以及面向沙箱任务的结构化文件夹上传。此版本包含 [PR #31](https://github.com/hjxwz123/Aivory/pull/31) 中贡献的工作。

##### 统一的产物面板

- 在同一个右侧面板中打开流式 HTML 产物、对话附件、沙箱输出和知识库文档，同时保持对话可见。
- 使用指针或键盘调整桌面面板大小。所选宽度会被保存、限制在视口范围内，并为聊天栏留出可用空间。
- 文档预览和编辑使用同一面板外壳，并提供移动端侧边面板和错误边界；发生错误时可重试，而不会留下空白界面。
- 通过共享的沙箱化框架渲染不可信 HTML。在纯 HTTP 部署中，公开预览不再错误地将同源资源升级为 HTTPS。

##### 浏览器文档编辑

- 使用 CodeMirror 编辑文本、源代码和 HTML。编辑 HTML 时，旁边的实时预览会同步更新。
- 在浏览器中编辑 DOCX 文档，并将编辑后的 OOXML 包序列化，以供下载或另存为新副本。
- 在无障碍网格中编辑 XLSX 单元格，保留未修改的包内容，并计算受支持的公式。
- 编辑现有 PPTX 幻灯片中的文本运行，并从修改后的文件刷新演示文稿预览。
- 下载当前编辑结果，或将其保存为新的附件副本。编辑器仅在需要时加载，以免其较大的依赖进入初始路由。

文档编辑有意按格式分别实现。PPTX 编辑仅修改现有文本，不会添加、移动或重新设计幻灯片对象。XLSX 编辑上限为 2,000 行和 100 列，且未实现完整的 Excel 计算引擎。复杂的 Office 文档在视觉呈现上仍可能与桌面版 Office 应用不同。

##### 文件夹上传和沙箱任务

- 从桌面编辑器工具栏或移动端附件菜单中选择整个文件夹。
- 在 SQLite 或 PostgreSQL 中保留每个已接受文件的相对路径，并将其暂存到 `/workspace/uploads/<folder>/<path>`。
- 在上传前过滤依赖项和构建目录、系统文件、不允许的扩展名、无扩展名文件，以及超过数量或总大小限制的选择。编辑器会报告跳过的内容。
- 以受控并发上传已接受的文件，并将整个文件夹显示为一个可展开的附件节点，包含总大小、进度和失败状态。
- 生成 `/workspace/aivory-uploads.txt`，以便模型在使用 `python_execute` 执行项目和目录任务前检查目录树。
- 在 API 边界验证相对路径，并保留沙箱侧路径包含性检查，作为防止路径遍历的第二道防线。

文件夹上传有意绕过两条文档 RAG 摄取路径；模型会直接从沙箱读取文件。对话文件抽屉仍会逐个列出文件夹成员，浏览器选择器无法表示空目录，而包含 300 个已接受文件的文件夹仍会发起 300 个文件请求，并发数限制为三。

##### 兼容性和部署

- 通过 SQLite 和 PostgreSQL 自动迁移添加 `files.rel_path` 数据库列。现有单文件附件保持原有行为。
- 添加延迟加载的 CodeMirror、DOCX、电子表格和 OOXML 依赖。
- 将 `package-lock.json` 与新增依赖同步，使生产 Docker 构建继续使用 `npm ci`。

感谢 [@357929231](https://github.com/357929231) 在 [PR #31](https://github.com/hjxwz123/Aivory/pull/31) 中设计并实现统一的产物面板、文档编辑器和结构化文件夹上传工作流。其原始提交和作者身份已保留在仓库历史中。

## v2.4.9 系列

### [v2.4.9](https://github.com/hjxwz123/Aivory/releases/tag/v2.4.9) — 2026-09-22 — 正式版

#### Aivory v2.4.9

`v2.4.9` 是 2.4.9 系列的稳定版本。它汇集了 beta.1 至 beta.6 中的最终功能：TypeSafe/Jev 决策策略、更智能的工具路由、更完善的工作区和域管理、公开 HTML 预览、企业微信登录、Tavily 搜索，以及 Responses 兼容性修复。

本更新日志涵盖自 `v2.4.8` 以来的所有变更，包括从该稳定版本直接升级的用户。

##### TypeSafe / Jev 决策策略

- 在管理员设置中配置 TypeSafe 渠道、API 密钥和 Jev 模型。凭据、模型版本、价格和策略选择都会保存到数据库中；无需设置 TypeSafe 环境变量。
- 在 **Model policy** 下，分别为工具路由、记忆去重、记忆冲突裁定、内容审核和文件路由选择 Jev。
- 文件路由涵盖文档使用策略以及多个文档之间的选择，包括覆盖完整文档。检索使用原始问题；摘要和其他文本生成仍由聊天模型处理。
- 共享决策客户端支持 **Choice**、**Score** 和 **Noul**，并提供响应验证、有界超时、模型版本检查、仅元数据日志记录、用量核算和每日令牌配额处理。
- 对不确定的工具决策，保留完整工具集。对不确定的记忆决策，避免合并并标记未解决的冲突。不确定或失败的审核会回退到已配置的关键词检查；文档路由失败则回退到检索。
- 决策模型不会出现在公开聊天目录中，也不会用于需要文本生成的策略。在审核设置中配置审核类别和关键词，然后为相关聊天模型启用模型审核。
- 将 **Other internal task model** 放在 **Default conversation model** 后面，以便于配置。

决策阈值是初始默认值。集成测试使用模拟响应；请根据自身部署的样本评估真实模型的准确性和中文阈值。参见 [TypeSafe 配置与行为](https://github.com/hjxwz123/Aivory/blob/v2.4.9/docs/typesafe-decisions.md)。

##### 工具路由、网页搜索和图像参考

- **Auto** 会区分目标明确的网页搜索请求和需要完整工具集的工作。复杂调查、来源验证、完整页面阅读、代码执行、文件操作、图像生成或编辑、记忆写入、指定技能和自定义工具都会保留完整的解析后工具集。
- 当确定性完整工具信号或少量工具声明表明无需额外决策请求时，跳过路由模型。路由失败时回退到完整工具集。
- 如果允许并配置了 Aivory 搜索，**Off** 允许仅通过搜索来回答。仅搜索模式支持**最多三次搜索工具调用**，包括独立查询的批次，因此模型可以在根据现有结果作答前进一步优化搜索。
- 如果仅搜索路径可用，**Search before answering** 会要求在最终回答前先进行搜索。
- 在 Serper、Brave 和 SearXNG 之外添加 **Tavily**，并在引导流程和工具设置中提供 API 密钥配置及就绪状态检查。
- 在受支持的图像生成请求中加入当前轮次上传的参考图像，包括创建新图像的请求。
- 简化可见的工具选择器，同时保留其状态、计数和无障碍标签。

### [v2.4.2](https://github.com/hjxwz123/Aivory/releases/tag/v2.4.2) — 2026-08-29 — 正式版

##### 更新内容

Aivory 2.4.2 改进了身份验证策略、多设备会话、模型可用性强制检查，以及管理员对默认工具行为的控制。此版本还为快速模式提供了独立的工具预算，修复了网页读取和直接图像生成的失败处理路径，并支持将 `markdown.new` 用作兼容 Jina 的 Reader 回退服务。

###### 身份验证与账户访问

- 将密码注册与 OAuth/OIDC 自动账户创建分离。管理员现在可以关闭直接通过邮箱/密码注册的功能，同时仍允许首次使用的用户通过已启用的第三方身份提供商注册。
- 确保注册页面在仅允许身份提供商注册的模式下仍可使用：OAuth 按钮保持可用，密码注册表单则隐藏，同时管理员设置页面仅提交实际发生更改的设置。
- 使用浏览器 Credential Management API，在登录页面添加“记住密码”选项。Aivory 不会在服务端添加明文密码存储；不支持此 API 的浏览器会保留其正常的密码管理器行为。
- 允许同一账户在多台电脑和手机上保持登录状态。新登录会追加一个设备会话，而不是撤销所有现有的刷新会话。
- 保留现有的刷新令牌重放保护，并在提交新会话时验证账户状态、令牌代次、密码/2FA 安全状态以及 OAuth 提供商状态，防止过时的登录操作与安全设置变更发生竞态。

###### 模型与渠道可用性

- 在保存默认、任务、工具路由、验证或回退模型策略时，拒绝已禁用的模型、非聊天模型、关联到已禁用渠道的模型，以及不受支持的渠道。
- 从管理员策略选择器中过滤掉不可用的模型，并显示本地化的配置错误，而不是保存无法运行的模型。
- 在对话开始时再次强制检查渠道可用性，使禁用渠道能够立即阻止其在运行时被使用。
- 在执行时跳过已配置但不可用的任务模型和工具路由模型。内部任务会依次回退到当前对话模型和全局默认模型，前提是相应模型可用；Auto 工具路由会回退到当前对话模型。

###### 默认工具模式

- 添加管理员级别的默认工具模式，提供 `Auto`、`On` 和 `Off` 选项。
- 仅当用户未选择账户级别的默认模式，且请求未明确选择模式时，才应用部署默认值。现有的用户显式选择和每轮对话的选择仍然优先。
- 在已通过身份验证的个人资料中返回实际生效的默认值，以便消息编辑器和 API 确定相同的行为。

###### 快速模式与工具可靠性

- 为快速模式提供独立的各工具使用次数限制、系统工具调用总次数限制，以及耗时预算，不再按普通模式的固定比例推算这些限制。
- 在快速模式下保持所有由提供商托管的工具可用。本地系统工具仅在其快速模式限制为 `0` 时隐藏；正数限制会使相应工具可用，并对其单独设置使用上限。
- 将每次本地系统工具调用尝试都计入总次数限制，包括失败的尝试，因此交替使用工具或重复出错都无法绕过每轮对话的上限。
- 延长网页读取的执行时间，使直接读取尝试可以快速失败，同时为配置的 Reader 回退服务留出时间，并在只有部分页面可读取时保留批量读取的部分结果。
- 在规范化直接图像生成请求时移除无关的 `base_image_index` 字段。过时的索引不再导致 `action=generate must not set base_image_index`，基于规范形式的重复检测也不再因先前的无效载荷而阻止修正后的请求。

- 添加 `AIVORY_TOOLS_WEB_FETCH_JINA_URL_MODE`。默认的 `escaped` 模式保留 `r.jina.ai` 的行为；`raw` 会追加原始目标 URL，以支持 `https://markdown.new` 等兼容服务。

- 在所有受支持语言（英语、简体中文、繁体中文、日语、法语）的沙箱使用指引中说明上传文件的可用情况。

###### 公开图片下载（`fetch_image`）

- 通过 `fetch_image` 工具重新启用向对话沙箱下载图片的功能。Python 运行器保持网络隔离；所有出站访问均通过后端具备 SSRF 防护的客户端进行。
- 校验 URL 协议、主机和端口，拒绝私有网络、环回地址和元数据服务目标，强制执行字节数上限，并在暂存前验证下载的字节是否属于受支持的图片。
- 将验证通过的图片暂存到 `/workspace/downloads/`，在不同轮次之间保留沙箱会话，并在容器被回收后重建会话。
- 为沙箱中的图片边界情况添加信号和数据覆盖，包括会话丢失后的重建以及工作区策略拒绝的情况。
- 为 `fetch_image` 添加每轮调用限制和 Deep Research 调用限制，以及每次调用的下载超时；这些设置均可通过环境变量调整，并已记录在 `docs/config-reference.md` 中。
- 在快速轮次中，与 `python_execute` 一样禁用 `fetch_image`，并使其受 `AllowSandbox` 工作区策略约束。
- 在可选的内置工具目录中添加“下载图片”条目。

###### OpenAI 聊天在多轮工具调用之间的推理

- 在重放先前的 OpenAI 聊天轮次时，根据请求重放 `reasoning_content`，以便正确转发早期轮次中生成的推理块。
- 将 OpenAI 聊天的推理增量流式传入与非推理内容相同的工具循环事件中，恢复较长的、启用工具的对话中推理显示的连续性。
- 添加多轮工具循环中推理重放的回归测试覆盖。

###### 网页抓取的稳健性

- 当无法直接访问源站时（路由被过滤或陷入黑洞），通过兼容 Jina Reader 的文本提取端点重试读取，而非一直挂起直到工具预算耗尽。

### [v2.2.13](https://github.com/hjxwz123/Aivory/releases/tag/v2.2.13) — 2026-08-16 — 正式版

##### 变更内容

Aivory 2.2.13 改进了图像生成的可靠性、图像附件处理、工具选择、Gemini 函数调用和长对话压缩行为。此外，还为提供商诊断新增了请求体隐私控制，将模型级别的 MCP 工具改为需显式启用，使主侧边栏更加紧凑，并优化了共用消息输入框的聚焦样式。

###### 图像生成可靠性

- 为直接使用图像模型的对话和 `image_generate` 内置工具添加了一次性备用通道。

### [v2.2.10](https://github.com/hjxwz123/Aivory/releases/tag/v2.2.10) — 2026-08-14 — 正式版

##### 更新内容

Aivory 2.2.10 完善了长对话的上下文压缩生命周期，并提升了长篇回复在持续流式输出时的渲染性能。压缩现在能保留更多安全续接对话所需的信息，通过有界的摘要请求处理庞大的历史记录，正确结算自身用量，并在编辑、删除、分支、并发请求及多个应用副本之间保持一致。在前端，已完成的 Markdown 区块不会再因回复末尾不断增长而重复执行高开销的渲染工作。

###### 自动与手动上下文压缩

- 达到配置的 token 阈值后，自动压缩较早的已完成对话历史，同时原样保留近期消息。
- 在存储中保留完整的可见对话。压缩只改变发送给模型的历史上下文，不会删除用户的原始消息。
- 同时保留最低数量的近期用户与助手对话轮次，以及按配置百分比确定的近期消息，使当前指令和正在进行的工作不被纳入摘要。
- 支持通过 `/compact` 显式执行压缩；对于压缩已禁用、历史记录不足、正在生成回复、对话已更改、模型失败、持久化失败和超时等情况，均提供稳定的处理结果。
- 为自动压缩增加实时的开始、完成和失败通知，避免后台工作看起来无声无息或停滞不前。
- 使用可配置的宽限时间窗口处理遗留的 `streaming` 消息，避免生成过程崩溃后无限期阻止后续手动压缩。

###### 摘要质量与请求限制

- 将固定的短摘要目标改为根据来源内容大小和对话轮次调整的自适应目标，以保留长对话中的更多决策、约束、未完成工作和事实细节。
- 当来源内容足以支撑所请求的目标长度，而生成的摘要明显过短时重试；不会为确实简短或信息稀疏的对话填充内容。
- 通过有界的 map-reduce 阶段处理过大的摘要来源内容，避免单个请求超出所选模型的上下文窗口。
- 增加由管理员控制的单次压缩请求预算，默认值为 32,768 tokens，最小值为 8,192 tokens；更长的历史记录会在该预算内拆分并逐步合并。
- 在提供商请求中强制执行配置的摘要输出上限。模型的推理或思考默认设置不能悄然提高管理员设定的压缩硬性限制。
- 限制累计摘要区块的大小，并在超出配置的合并预算时，按对话顺序将其折叠合并。

###### 完整的工具、引用与附件上下文

- 从提供商数据中恢复完整的、可识别的原生工具结果以供摘要使用，而不再仅依赖规范化聊天区块中存储的简短预览。
- 必要时将完整结果拆分到多个有界的 map-reduce 请求中，以保留长篇搜索、论文检索、网页、数据库及其他工具结果末尾的重要结论。
- 使用与提供商无关的内部工具封装格式，使 OpenAI、Anthropic 和 Gemini 的工具历史都能用于摘要，而无需将某一提供商的原生负载交给另一提供商重放。
- 将引用标题、URL、摘录、附件元数据、文档引用和生成产物的详细信息加入压缩来源内容，使保留下来的引用仍可理解。
- 在压缩边界两侧保留图像和托管图像产物的引用，并在有界的总字节预算内，为兼容的视觉模型重新载入经过验证的图像。
- 完整的内部工具输出仍保持私有：常规对话 API 继续返回现有的有界预览，不会暴露为摘要而恢复的原始结果。

###### 计费、并发与数据一致性

- 为手动和异步压缩增加独立的额度预留、结算与释放流程，防止出现记录了正数用量、却从未从用户余额中扣除的情况。

### [v2.0.1](https://github.com/hjxwz123/Aivory/releases/tag/v2.0.1) — 2026-06-23 — 正式版

补丁版本：对代码执行沙箱（§4.5）进行全链路安全与可靠性审计，并新增沙箱执行超时和归档清理的管理界面。

###### 🔒 安全
- **加固管理员工作区预览。** 沙箱生成的文件此前以 `inline` 方式提供，内容类型由扩展名推断，且没有 `nosniff`/CSP，因此模型写入的 `.html`/`.svg` 文件可能在管理员域名下执行脚本（存储型 XSS）。现在设置 `X-Content-Type-Options: nosniff` + 严格的 `Content-Security-Policy: default-src 'none'; … sandbox`，仅以内联方式呈现不具备脚本执行能力的图片/PDF/文本类型，并将其他所有类型强制作为 `application/octet-stream` 下载。

###### 🧱 可靠性
- **工具发生 panic 不再导致 API 崩溃。** 并发工具运行器会启动子 goroutine，请求作用域内的 `recover` 无法捕获其中的 panic；未恢复的 panic 会使整个进程崩溃。现已为工具运行器和归档 GC 循环添加 `recover()`。
- **空闲会话回收器不再终止刚使用过的会话。** 现在它会在会话锁内重新检查最后使用时间，然后才销毁容器，因此活跃对话不再丢失其 `/workspace`。
- **孤立的单元进程会被清理。** 单元分离出的后台进程（`subprocess` / double-fork / `setsid`）此前会在运行结束后继续存活，并耗用会话的 cpu/mem/pids 预算；现在每次执行都会附加一个环境变量标记，随后清理其整个进程树。
- **修复会话预置过程中的竞态问题** — 持久化失败时释放资源、在锁保护下重试已消失的会话，以及 `fetch_image` 现在与 `python_execute` 共用按对话划分的锁（避免容器泄漏）。
- 为产物收集设置总耗时上限、为 `MAX_SESSIONS` 预留操作加锁、使用 NUL 分隔的文件列表，并加入快速失败路径，使 `docker rm` 超时不再导致回收器线程退出。

###### 🛠 运维
- 沙箱 sidecar 新增 `/healthz` 健康检查 + `mem_limit` / `pids_limit`。
- 运行器镜像的依赖现在通过 `runner-requirements.txt` 固定版本，以实现可复现构建。⚠️ 在依赖该镜像之前，请验证运行器镜像能够成功构建。
- 新增管理员设置（界面 + i18n）：**执行超时**（`sandbox_exec_timeout_sec`）和**归档清理天数**（`storage_archive_ttl_days`）。
