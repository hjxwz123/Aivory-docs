# 域名入组与工作空间访问

平台管理员在两个独立页面管理组织访问：`/admin/workspaces` 创建工作空间并管理负责人；`/admin/domains` 将一个或多个邮箱域映射到工作空间，并控制已绑定成员的个人空间访问。

## 配置前准备

1. 在 `/admin/workspaces` 创建目标工作空间。
2. 按姓名或邮箱搜索一个已启用的现有账号作为工作空间管理员。该账号会在同一操作中成为所有者并加入成员。
3. 确认该账号没有被其他域规则锁定。平台管理员可以拥有个人空间，也可以负责多个工作空间。
4. 域规则要求密码注册验证时，先确认 SMTP 能正常投递。全局设置和命中的规则会共同生效：任一处要求验证，密码注册都必须验证邮箱。

## 创建工作空间并指定负责人

进入 **管理后台 → 工作空间 → 创建工作空间**。填写名称，按姓名或邮箱搜索已启用用户并选择管理员。候选人必须是已存在且符合条件的账号。服务端在一个事务中创建工作空间、成员关系、所有者关系和初始管理员角色；任一步失败都会整体回滚。

打开工作空间详情并点击 **更换管理员** 可以更换负责人。候选人列表只包含当前成员。新负责人获得所有者和管理员角色，原负责人降为普通成员，其他管理员角色保留；未使用的管理员邀请会在同一事务中撤销，并写入工作空间审计事件。

这个平台管理员操作与负责人自己的 **转移所有权** 流程不同：后者会让原负责人继续保留管理员身份；平台后台更换负责人会将原负责人降为普通成员。

## 添加邮箱域规则

进入 **管理后台 → 域名 → 添加域规则**，填写：

| 字段 | 含义 |
| --- | --- |
| 匹配域名 | 可填写 1 至 50 个如 `example.com` 的裸域名；不能写邮箱地址、协议、路径、通配符或尾部句点 |
| 工作空间 | 目标工作空间；创建后不可修改 |
| 停止自动加入 | 默认关闭。只有平台管理员手动开启，才会暂停后续账号的自动入组 |
| 密码注册验证 | 为命中的密码注册增加验证要求，并与全局设置共同生效 |
| 初始用户组 | 可选；只用于新注册且命中本规则的账号，手动加入时保留账号原有系统用户组 |
| 锁定个人空间 | 开启后，已绑定的普通用户只能进入指定工作空间 |

系统精确匹配邮箱最后一个 `@` 后的域名且不区分大小写。`user@example.com` 匹配 `example.com`，`user@sub.example.com` 不匹配。一个匹配域名只能属于一条规则；国际化域名需要填写 Punycode。编辑匹配域名列表只影响后续注册和验证策略匹配，不会解除已经存在的绑定。

每条新规则创建后立即启动自动加入。它只作用于规则启用后创建的非平台管理员账号。命中的密码注册，以及第三方登录返回命中邮箱的新账号，会在同一事务中完成入组、域绑定和工作空间成员关系。创建规则不会追溯加入已有账号；请在 **域用户** 中手动添加。域绑定以用户 ID 为键，之后修改邮箱不会解除限制。

## 锁定个人空间

启用 **锁定个人空间** 后，绑定的普通用户：

- 只能进入指定工作空间，不能切换到个人或其他工作空间；
- 不能创建工作空间、接受其他空间邀请或退出指定空间；
- 不能访问个人对话、文件、项目、知识库或其他个人空间资源；
- 即使客户端伪造 `workspace_id` 或直接打开个人 URL，服务端也会拒绝。

锁定个人空间本身不直接决定是否能使用工作空间私有对话。创建该类对话同时需要系统用户组和指定工作空间策略允许；它不会提供重新进入个人空间的路径。

用户原有个人数据会保留。锁定状态按请求从数据库读取，修改规则或单用户例外无需重新登录；在线客户端会收到新的访问状态，旧权限下的生成与上传快照会被撤销。

平台管理员不受域锁定影响。因此管理员可以使用个人空间，在个人空间与工作空间之间切换，也可以继续管理域规则。这个例外依据平台 `admin` 角色，而不是工作空间成员身份。

## 手动域成员与例外

打开规则的 **域用户** 列表可以手动管理成员。平台管理员可按姓名或邮箱搜索并添加任意正常或待验证账号，即使账号邮箱不匹配规则中的域名。候选列表会排除平台管理员、已停用账号和已经绑定其他域规则的账号。每批最多 500 个账号，并以事务执行：任何一个校验失败都会让整批都不写入。

手动加入会在同一事务内创建域绑定和工作空间成员关系，不会覆盖账号原有的系统用户组；即使已停止自动加入，管理员仍可手动添加。

同一列表可为每个已绑定账号选择三种实际状态之一：

| 状态 | 实际行为 |
| --- | --- |
| 遵循域规则 | 继承当前 `lock_personal` 值 |
| 仅工作空间 | 强制锁定此用户的个人空间 |
| 允许个人空间 | 覆盖规则，恢复个人空间访问 |

域级开关变化时，显式例外仍保持；选择 **遵循域规则** 才会恢复继承。恢复个人空间不会移除用户在指定工作空间的成员关系。

平台管理员也可随时移除单个成员。移除会解除域绑定和个人空间限制；仅当用户的工作空间成员关系原本由自动或手动域入组创建时，才一并移除。用户在绑定前已拥有的独立成员关系会保留；工作空间所有者不会因该操作被移出工作空间。

## 历史个人对话

已有账号被手动加入一个锁定个人空间的域，且个人空间仍有对话时，登录会显示个人数据处置弹窗。用户可以：

- **下载副本**：将历史个人对话与消息导出为可移植的 Aivory ZIP。下载不会移动或删除服务端数据。
- **迁移到工作空间**：仅当该成员拥有“创建工作空间私有对话”权限时可用。迁入后，普通成员无法查看他人的私有对话；工作空间所有者和管理员仍保留其正常管理权限。
- **暂时忽略**：关闭提示，不处理也不删除数据。侧栏头像菜单会保留 **数据管理**，之后可重新打开同一弹窗。

迁移会保留消息、附件、收藏/置顶和归档状态以及对话树。个人项目和个人知识库关联不能跨工作空间引用，因此会被清除。任一适用权限层禁止创建私有对话时，迁移不可用，但下载仍可用。

## 停止、修改或删除规则

- **停止自动加入**：规则创建后默认运行。只有平台管理员手动开启 **停止自动加入**，才会暂停后续自动入组。已有绑定和限制继续生效，且不影响手动添加。
- **修改匹配域名**：可以增删规则中的匹配域名，只影响后续匹配；同一域名不能同时分配给其他规则。
- **修改目标工作空间**：创建后不支持修改，避免静默迁移用户和数据。需要更换时应删除原规则再创建新规则。
- **删除规则**：先查看影响说明并确认。删除会解除该规则下所有绑定和个人空间锁定，但保留已有工作空间成员关系和数据。
- **删除工作空间**：先删除所有引用它的域规则。数据库使用 `ON DELETE RESTRICT`，避免锁定用户被留在不存在的工作空间。

如果用户在临时允许个人空间期间退出了指定空间，管理员重新启用锁定时系统会恢复其成员关系，确保仍有可进入的空间。

## 数据与备份影响

关系库在 `registration_domains` 保存规则，在 `registration_domain_matches` 保存匹配域名，在 `domain_users` 保存用户绑定。`registration_domains.workspace_id` 使用 `ON DELETE RESTRICT`；绑定关系对用户和规则使用 `ON DELETE CASCADE`。规则、匹配列表、绑定、个人空间状态及关联文件均应纳入逻辑与物理备份。

恢复或迁移时：

1. 先恢复包含三张域表的关系数据库，再开放注册。
2. 在同一一致性点恢复工作空间成员、文件等数据。
3. 启动应用，让幂等迁移校验结构并重新加载权限。
4. 对命中域规则的新注册、手动加入的历史账号、允许和禁止私有对话迁移两种情形，以及尝试切换空间的锁定用户分别做验收，再对外开放实例。

参见[数据库总览与运维](../reference/database/overview.mdx)了解 schema、外键及 SQLite/PostgreSQL 差异；完整恢复顺序见[升级、备份与恢复](../deployment/upgrade-backup.mdx)。

## 故障速查

| 现象 | 检查项 |
| --- | --- |
| 命中域名的新用户没有入组 | **停止自动加入** 已开启、邮箱未精确匹配配置域名，或密码注册验证未完成 |
| 规则中没有已有用户 | 自动入组只面向未来注册；请从该规则的 **域用户** 列表手动添加 |
| 无法选择手动添加候选人 | 账号是平台管理员、已停用，或已绑定到另一条域规则 |
| 用户仍能看到个人数据 | 检查单用户实际状态和请求是否命中当前数据库；平台管理员角色不受锁定 |
| 删除工作空间被拒绝 | 仍有 `registration_domains` 行引用它；先删除这些规则 |
| 用户改邮箱后仍被锁定 | 这是预期行为：`domain_users` 以 `user_id` 为键；修改例外、移除成员或删除规则 |
