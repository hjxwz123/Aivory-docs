## v2.5.0 series

### [v2.5.0-beta.5](https://github.com/hjxwz123/Aivory/releases/tag/v2.5.0-beta.5) — 2026-09-25

#### Aivory v2.5.0-beta.5

This release includes PR #36's AI PPT workbench and layered permissions, followed by direct folder uploads to conversation sandboxes.

##### AI PPT

- Restore AI PPT with Aivory's own presentation workflow instead of the retired embedded vendor interface. The browser uses Aivory endpoints; the Docmee API key and calls remain server-side.
- Align the presentation UI with the rest of the site, including outline editing, template selection, deck listing and preview.
- Administrators control AI PPT access per user group. Workspace administrators control the workspace policy and member access. Effective access requires every applicable layer to allow it; guests cannot use AI PPT.
- Generation and paid edits continue to use the credit and usage records described in the [AI PPT guide](https://github.com/hjxwz123/Aivory/blob/v2.5.0-beta.5/docs/ai-ppt-docmee.md).

##### Folder Uploads

- Show **Upload folder** only when a sandbox is configured and the user group and workspace allow file upload and the sandbox tool.
- Send the selected directory in one request. Keep its original bytes and relative paths under `/workspace/folders/<folder>/` in the current conversation sandbox. No per-file document ingestion, image conversion or RAG indexing occurs.
- Enforce path safety and limits of 300 files, 200 MiB per folder and 40 MiB per file. Directory drag-and-drop cannot fall through to ordinary file attachments.
- Ordinary file uploads are unchanged. If a sandbox write fails partway through, some already-written files may remain; the UI reports this. See the [folder upload guide](https://github.com/hjxwz123/Aivory/blob/v2.5.0-beta.5/docs/folder-upload.zh-CN.md).

##### Validation

- 140 frontend test files and 824 tests passed.
- Go API, store and tools tests passed; the production frontend build passed.
- No screenshot tests were run.

##### Upgrade

This is a test release. Back up the database and application data before deploying. Database migrations run on application startup. AI PPT requires an enabled Docmee configuration; folder upload requires a configured sandbox.

After the application, updater and both sandbox images finish publishing, set the deployment's actual `deploy/.env` to the new image tag:

```dotenv

```

Remove or align any explicit `APP_IMAGE_TAG` or `SANDBOX_IMAGE_TAG` overrides, then verify and deploy:

```bash

docker compose --env-file .env -f docker-compose.prod.yml pull
docker compose --env-file .env -f docker-compose.prod.yml up -d --no-build
```

### [v2.5.0-beta.4](https://github.com/hjxwz123/Aivory/releases/tag/v2.5.0-beta.4) — 2026-09-23

#### Aivory v2.5.0-beta.4

This release adds image reading for conversations using a text-only model. An administrator can select an enabled, vision-capable chat model under **Settings > Model policy**. When configured, that model reads attached images and supplies structured text evidence to the selected conversation model. Models with native vision continue to receive images directly. Leaving the setting empty keeps the existing image-skipping behavior for text-only models.

In regular conversations, image evidence is cached with the uploaded file and regenerated when the vision model or evidence prompt version changes. A turn makes at most four new vision calls; cached evidence remains available without that limit. Private chat stores no image cache and reads only images on the newest user turn. If image reading fails, the conversation can continue without the unavailable image.

Vision reads are recorded as `task.vision_caption` usage and may add latency and model costs. This release does not restore the AI PPT integration removed in beta.3; ordinary PPTX preview and editing remain available.

### [v2.5.0-beta.1](https://github.com/hjxwz123/Aivory/releases/tag/v2.5.0-beta.1) — 2026-09-22

#### Aivory v2.5.0-beta.1

`v2.5.0-beta.1` introduces a unified, resizable artifact panel, browser-based document editing, and structured folder uploads for sandbox tasks. This release contains the work contributed in [PR #31](https://github.com/hjxwz123/Aivory/pull/31).

##### Unified artifact panel

- Open streamed HTML artifacts, conversation attachments, sandbox outputs and knowledge-base documents in one right-side panel while keeping the conversation visible.
- Resize the desktop panel with a pointer or keyboard. The chosen width is persisted, clamped to the viewport and leaves usable space for the chat column.
- Use the same panel shell for document preview and editing, with a mobile side sheet and an error boundary that offers retry instead of leaving a blank surface.
- Render untrusted HTML through the shared sandboxed frame. Public previews on plain-HTTP deployments no longer upgrade same-origin assets to HTTPS incorrectly.

##### Browser document editing

- Edit text, source code and HTML with CodeMirror. HTML edits update a live preview beside the editor.
- Edit DOCX documents in the browser and serialize the edited OOXML package for download or saving as a new copy.
- Edit XLSX cells in an accessible grid, preserve unmodified package content and calculate supported formulas.
- Edit text runs in existing PPTX slides and refresh the presentation preview from the patched file.
- Download the current edited result or save it as a new attachment copy. Editors are loaded only when needed to keep their larger dependencies out of the initial route.

Document editing is intentionally format-specific. PPTX editing changes existing text only; it does not add, move or redesign slide objects. XLSX editing is capped at 2,000 rows and 100 columns and does not implement the full Excel calculation engine. Complex Office documents may still differ visually from desktop Office applications.

##### Folder upload and sandbox tasks

- Select an entire folder from the desktop composer toolbar or the mobile attachment menu.
- Preserve each accepted file's relative path in SQLite or PostgreSQL and stage it under `/workspace/uploads/<folder>/<path>`.
- Filter dependency and build directories, system files, disallowed extensions, extensionless files and selections over the count or total-size limits before upload. The composer reports what it skipped.
- Upload accepted files with controlled concurrency and show the folder as one expandable attachment node with aggregate size, progress and failure state.
- Generate `/workspace/aivory-uploads.txt` so the model can inspect the directory tree before using `python_execute` for project and directory tasks.
- Validate relative paths at the API boundary and retain sandbox-side path containment as a second defense against traversal.

Folder uploads intentionally bypass both document RAG ingestion paths; the model reads them directly from the sandbox. The conversation file drawer still lists folder members individually, empty directories cannot be represented by the browser picker, and a folder with 300 accepted files still performs 300 file requests with concurrency limited to three.

##### Compatibility and deployment

- Add the `files.rel_path` database column through automatic SQLite and PostgreSQL migrations. Existing single-file attachments retain their previous behavior.
- Add lazy-loaded CodeMirror, DOCX, spreadsheet and OOXML dependencies.
- Synchronize `package-lock.json` with the new dependencies so the production Docker build can continue using `npm ci`.

##### Community contribution

Thank you to [@357929231](https://github.com/357929231) for designing and implementing the unified artifact panel, document editors and structured folder-upload workflow in [PR #31](https://github.com/hjxwz123/Aivory/pull/31). Their original commit and authorship are retained in the repository history.

### [v2.4.9](https://github.com/hjxwz123/Aivory/releases/tag/v2.4.9) — 2026-09-22

#### Aivory v2.4.9

`v2.4.9` is the stable release of the 2.4.9 series. It brings together the final functionality from beta.1 through beta.6: TypeSafe/Jev decision policies, smarter tool routing, stronger workspace and domain management, public HTML previews, WeCom sign-in, Tavily search, and Responses compatibility fixes.

This changelog covers all changes since `v2.4.8`, including users upgrading directly from that stable version.

##### TypeSafe / Jev decision policies

- Configure TypeSafe channels, API keys and Jev models in administrator settings. Credentials, model versions, prices and policy selections are saved in the database; no TypeSafe environment variables are required.
- Select Jev independently for tool routing, memory deduplication, memory conflict adjudication, content moderation and file routing under **Model policy**.
- File routing covers document-use strategy and selection across multiple documents, including full-document coverage. Retrieval uses the original question; summaries and other text generation continue through chat models.
- A shared decision client supports **Choice**, **Score** and **Noul**, with response validation, bounded timeouts, model-version checks, metadata-only logging, usage accounting and daily token quota handling.
- Uncertain tool decisions retain the full tool set. Uncertain memory decisions avoid merging and mark unresolved conflicts. Uncertain or failed moderation falls back to configured keyword checks; failed document routing falls back to retrieval.
- Decision models stay out of the public chat catalog and policies that require text generation. Configure moderation categories and keywords in moderation settings, then enable model moderation for the relevant chat models.
- Place **Other internal task model** immediately after **Default conversation model** for easier configuration.

Decision thresholds are initial defaults. Integration tests use simulated responses; evaluate real-model accuracy and Chinese-language thresholds against your own deployment's samples. See [TypeSafe configuration and behavior](https://github.com/hjxwz123/Aivory/blob/v2.4.9/docs/typesafe-decisions.md).

##### Tool routing, web search and image references

- **Auto** distinguishes focused web-search requests from work requiring the full tool set. Complex investigation, source verification, full-page reading, code execution, file work, image generation or editing, memory writes, named skills and custom tools retain the full resolved tool set.
- Skip the routing model when deterministic full-tool signals or a small tool declaration make an extra decision request unnecessary. A routing failure falls back to the full tool set.
- **Off** allows search-only answering when Aivory search is permitted and configured. Search-only mode supports **up to three search-tool calls**, including batches of independent queries, so the model can refine a search before answering from the available results.
- **Search before answering** requires a search before the final answer when the search-only path is available.
- Add **Tavily** alongside Serper, Brave and SearXNG, with API-key configuration and readiness checks in onboarding and tool settings.
- Include current-turn uploaded reference images in supported image-generation requests, including requests to create a new image.
- Simplify the visible tool selector while retaining its state, counts and accessible labels.

##### Domain enrollment and personal data

- Allow up to 50 exact matching domains in a rule. New rules begin automatic enrollment; **Stop automatic enrollment** pauses future automatic enrollment without affecting existing bindings or manual enrollment.
- Let platform administrators manually add eligible active or pending-verification users even when their email does not match the rule. Exclude accounts already bound to another rule, platform administrators and disabled accounts.
- Removing a domain binding preserves independently pre-existing workspace membership.
- Show a personal-data resolution dialog at login when an existing user's personal space becomes locked. Users can download an Aivory ZIP, migrate personal conversations into workspace-private conversations when policy permits, or revisit the action from **Data management**.
- Migration preserves messages, attachments, favorites, archive state and conversation trees, while clearing personal project and knowledge-base associations that cannot cross the workspace boundary. Download remains available when private-conversation migration is prohibited.
- Enforce domain subscription purchase restrictions and add search when selecting initial user groups.

##### Workspace profiles, administration and interface

- Let platform administrators configure domain icons and descriptions, and workspace administrators edit their workspace profile. Store profile settings in the database and display the icon beside the workspace name in the sidebar.
- Preserve the dedicated workspace management dialog for administrators, with **General**, members, invites, policy, announcements, audit and statistics. Edit the workspace icon and description under **General**.
- Add **Settings → Work** as a read-only workspace information page for both administrators and ordinary members, with a leave-workspace action only when permitted.
- The members menu opens the management dialog for administrators and **Settings → Work** for ordinary members. Ordinary members cannot browse the workspace member directory.
- Keep current group and credit information visible on the subscription page when workspace subscription purchases are disabled.
- Use the standard information dialog for announcements, with compact action and close controls and a default announcement title when none is configured. Improve announcement scrolling on desktop and mobile.
- Localize announcement editor controls in English, Simplified Chinese, Traditional Chinese, Japanese and French; authored announcement content is not automatically translated.
- Give sandbox browsing, sub-conversations and conversation file drawers a background distinct from the main chat across desktop, mobile, light and dark themes. Align sidebar workspace typography with the rest of the application.

##### Public HTML previews

- Create and copy public preview links from completed assistant HTML code blocks or the HTML preview header. Recipients can view the rendered document without signing in.
- Serve the preview document without the application shell. A CSP sandbox and opaque origin isolate it from Aivory cookies, storage and application DOM.
- Use a stable Tailwind runtime URL so shared previews remain renderable across application asset-hash changes.
- Check the publisher's current user-group sharing permission when creating and opening links. Revoking sharing disables existing links.
- Add administrator listing and deletion of public HTML previews, including owner and creation time. Deleted links no longer serve the document.

##### Authentication and provider reliability

- Add **Enterprise WeChat / WeCom** OAuth sign-in, including administrator configuration, callback state validation, provider-specific identities, backup and restore support, and localized settings.
- Recover stale registration captcha policies and protect single-use captcha tokens.
- Deduplicate identical streamed reasoning deltas returned simultaneously in `reasoning` and `reasoning_content`.
- Keep Responses commentary out of the final answer.
- When a Responses endpoint rejects a message ID for missing the `msg_` prefix, repair replayed message IDs and retry once on the same channel before recording a failure or selecting a fallback. Handle HTTP validation errors and errors delivered inside an SSE stream.
- Preserve message phase, reasoning state and tool-call associations. Successful repair does not create an Aivory failure usage row or duplicate token accounting; upstream services may still record rejected requests themselves.
- Apply the same repair to the final answer request after the tool execution limit. After the existing 20-round limit, tools remain disabled and the model uses the collected results to answer.
- Keep repair bounded: do not replay requests that already emitted output, and do not invoke channel fallback for repeated message-ID rejection. Other error handling keeps its existing behavior.

##### Stable and test release updates

- Show the latest stable release and latest GitHub prerelease separately in **System update**. Administrators can choose a newer beta or release candidate, while the sidebar update badge remains reserved for stable releases.
- Compare semantic versions correctly, including numbered beta versions and promotion from a beta to its final release.
- Restrict installation to versions returned by the configured GitHub release source; arbitrary image tags remain rejected.
- Refresh the bilingual README layout and brand headers.

##### Community contribution

Thank you to [BolshevikEric](https://github.com/BolshevikEric) for [PR #29](https://github.com/hjxwz123/Aivory/pull/29), which adds Tavily search and fixes duplicate reasoning deltas. Their original commits and authorship are retained in this release.

- All 120 frontend test files passed: 671 tests.
- The Go LLM regression suite passed, including Responses repair, tool finalization, routing and usage accounting.
- All 6 updater tests passed.

### [v2.0.1](https://github.com/hjxwz123/Aivory/releases/tag/v2.0.1) — 2026-06-23

Patch release: a full-chain security & reliability audit of the code-execution sandbox (§4.5), plus the admin UI for sandbox exec-timeout and archive cleanup.

###### 🔒 Security
- **Admin workspace preview hardened.** Sandbox-generated files were served `inline` with an extension-derived content-type and no `nosniff`/CSP, so a model-written `.html`/`.svg` could execute script on the admin origin (stored XSS). Now sets `X-Content-Type-Options: nosniff` + a strict `Content-Security-Policy: default-src 'none'; … sandbox`, renders only inert image/PDF/text types inline, and force-downloads everything else as `application/octet-stream`.

###### 🧱 Reliability
- **A tool panic no longer crashes the API.** The concurrent tool runner spawns child goroutines a request-scoped `recover` can't catch — an unrecovered panic took down the whole process. Added `recover()` to the tool runner and the archive-GC loop.
- **Idle reaper no longer kills a just-used session.** It now re-checks the last-used time under the session lock before tearing a container down, so an active conversation no longer loses its `/workspace`.
- **Orphaned cell processes are reaped.** Background processes a cell detached (`subprocess` / double-fork / `setsid`) survived the run and burned the session's cpu/mem/pids budget; each exec is now tagged with an env marker and its whole process tree is swept afterward.
- **Session-provisioning races fixed** — release-on-persist-failure, locked session-gone retry, and `fetch_image` now shares `python_execute`'s per-conversation lock (no leaked containers).
- Bounded artifact-collection wall-clock, `MAX_SESSIONS` reservation lock, NUL-delimited file listing, and a fast-fail path so a `docker rm` timeout can no longer kill the reaper thread.

###### 🛠 Ops
- Sandbox sidecar gains a `/healthz` healthcheck + `mem_limit` / `pids_limit`.
- Runner image dependencies are now version-pinned (`runner-requirements.txt`) for reproducible builds. ⚠️ Validate the runner image build before relying on it.
- New admin settings (UI + i18n): **execution timeout** (`sandbox_exec_timeout_sec`) and **archive cleanup days** (`storage_archive_ttl_days`).
