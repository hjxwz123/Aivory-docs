# 管理员首次配置

首次创建的账户自动成为管理员。进入 `/admin` 时，系统会显示可跳过、可重新查看的漫游引导；它把配置分为“能用”和“更好用”。即使跳过引导，也可以从管理员概览重新打开它。

个人版和完整版共享相同的管理员配置模型。区别是个人版默认没有本地 Python 沙盒，完整版默认已带有内部沙盒、PostgreSQL、Redis 和 Qdrant；不是两套不同的后台功能。

## 能用：只需要三步

完成以下三步后即可开始正常聊天。不要把任务模型、搜索、embedding、邮件或 Python 误当成首次聊天的硬性前置条件。

| 顺序 | 后台位置 | 完成标准 | 常见错误 |
| --- | --- | --- | --- |
| 1 | AI 与模型 → 渠道 | 至少一个渠道已启用，地址、接口格式和 API Key 可用 | Base URL 不匹配服务商格式，或使用无权限的 Key |
| 2 | AI 与模型 → 模型 | 至少一个关联该渠道的聊天模型已启用，模型请求 ID 非空 | 只添加了 embedding/图片/语音模型，或渠道被禁用 |
| 3 | AI 与模型 → 模型策略 | 选中一个仍可用的默认聊天模型 | 选中已经删除、禁用或失效的模型 |

完成后立即新建一条短对话验证真实上游响应。若收到渠道错误、额度错误或模型不存在，先修复渠道或模型，再继续配置其他能力。

## 第一步：创建可用渠道

在“渠道”中为每个模型服务商创建一条连接。渠道名只用于管理员识别；真正影响请求的是接口格式、Base URL、API Key 和启用状态。

- 选择与服务商匹配的 API 格式，不要仅凭模型名称猜测格式。
- OpenAI 兼容服务通常需要包含 `/v1` 的 Base URL，但具体路径仍以服务商文档为准。
- API Key 是服务端密钥，只在后台持久化保存；不要写进浏览器环境变量、公开前端配置、截图或日志。
- 建议一条渠道只代表一个可独立轮换、可独立停用的上游凭据。需要区分区域、账号、额度或网关时，创建多条渠道更容易排障。

渠道保存并启用后，再进入模型页。渠道本身不会自动让所有模型出现在用户选择器中。

## 第二步：添加聊天模型

模型是渠道下具体可调用能力的记录。添加模型时至少确认：它是聊天类型、关联了正确渠道、请求 ID 与服务商实际模型 ID 完全一致、状态已启用。

支持模型列表接口的渠道可以使用“自动添加渠道支持的模型”导入。导入失败并不一定表示渠道无法聊天，常见原因是服务商不开放模型列表权限、网关未实现该接口或 Key 只允许推理；这种情况下可手动添加模型 ID。

不同渠道可以重复使用相同模型 ID。例如渠道 A 和渠道 B 都有 `gpt-5`，可以创建两条 `gpt-5` 模型记录；它们通过各自的渠道关联区分，可分别设置排序、标签、配额和启用状态。

## 第三步：设置模型策略

在“模型策略”中选择默认聊天模型。它是新对话的默认选择，也是系统验证最小可用状态时检查的目标。

其余策略按实际需求添加：

- 任务模型：用于部分后台或辅助任务。它是健康建议，不是普通聊天的必需项。
- 工具路由模型：在自动工具模式下帮助判断是否需要调用工具；不配置时可使用主模型的常规策略。
- 校验模型：用于答案校验或审计；关闭时不会阻止聊天。
- 回退模型与首 token 等待阈值：上游慢、超时或不可用时的降级策略。应使用已验证、成本可控的模型。

每次改完策略都做一次真实对话。不要只依赖下拉框里存在模型，因为渠道凭据、服务商余额与模型授权可能随后改变。

## 更好用：按使用场景逐项启用

完成三步后，按下面的优先级扩展，而不是在首日一次性打开所有开关。

| 能力 | 先配置什么 | 何时需要 | 个人版与完整版差异 |
| --- | --- | --- | --- |
| 知识库与 RAG | embedding 模型、正确维度、文档解析策略 | 需要让回答基于私有文档 | 个人版用 SQLite 内嵌向量，完整版用 Qdrant |
| 网页搜索 | 搜索服务商和 API Key/地址 | 需要实时互联网信息 | 配置方式相同 |
| Python 与文件执行 | 可访问的沙盒、资源限制、模型工具授权 | 需要计算、图表、文件生成 | 个人版默认无本机沙盒；完整版默认内置 |
| MCP、技能、提示词 | 从低风险的单个服务或技能开始 | 需要连接外部业务系统 | 配置方式相同 |
| 邮件 | SMTP、发件地址和 TLS | 验证邮箱、重置密码、运营通知 | 完整版长期多人部署更建议优先配置 |
| OAuth 与注册策略 | 先验证 HTTPS 域名和单个身份源 | 需要第三方登录或组织入口 | 配置方式相同 |
| 工作区、套餐和支付 | 权限、配额、积分和支付回调 | 面向团队或商业用户 | 配置方式相同，完整部署更适合长期运营 |

有关 RAG、工具和沙盒的安全边界见[知识库、RAG 与存储](./knowledge-rag.mdx)和[工具、MCP 与沙盒](./tools-sandbox.mdx)。

## 配置优先级与变更管理

管理员后台的连接与系统设置会持久化保存。环境变量主要承担启动默认值、部署拓扑和不可由普通管理员直接修改的限制；二者不是可随意混写的一组表单。

- 渠道 API Key、支付凭据、SMTP、OAuth、对象存储、搜索与多数功能开关应在后台配置，并限制管理员访问。
- 官方 Docker Compose 对数据库、Redis、Qdrant 和内置沙盒等连接有明确的高优先级值；在 `.env` 添加同名变量未必会覆盖它。
- 环境变量修改后通常需要重启应用或沙盒；后台页面保存的设置按页面提示立即或在下一次请求生效。
- 导出管理员配置会包含渠道、OAuth、SMTP、存储和搜索等敏感凭据。把配置导出文件当作密码库级别的机密保存。

建议在投入真实用户前建立一份“变更后验收”清单：管理员和普通用户登录、默认模型对话、上传小文件、知识库检索、一个受限工具调用、备份导出，以及需要时的 OAuth 回调和支付测试。
