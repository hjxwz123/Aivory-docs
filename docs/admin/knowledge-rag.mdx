# 知识库、RAG 与存储

知识库让模型在回答前检索受限范围内的文档片段。可靠的 RAG 不是只上传文件：它依赖可用的 embedding、正确的维度、成功的解析和索引、适合的存储边界，以及对用户和工作区的访问控制。

## 工作流与验收点

典型流程如下：

1. 用户上传文件或管理员创建知识库资源。
2. 系统校验大小和类型，保存原始对象。
3. 解析器提取文本、表格或图片相关内容。
4. 文本被切分，embedding 模型生成向量。
5. 向量和文档元数据写入当前部署的向量后端。
6. 用户提问时，系统只检索其拥有访问权限的范围，并将相关片段作为上下文提供给模型。

上传完成不等于已经可检索。应等待文档状态显示为已完成，再用文件中可精确验证的一句话进行检索测试。失败时保留原文件、查看任务错误和模型/服务日志，不要反复上传同一文件来掩盖根因。

## Embedding 模型与维度

在渠道与模型中添加真正的 embedding 模型，或设置部署级 embedding 回退。无外部 embedding 时系统可以用基础本地 embedding 兜底，适合试用，但不应作为高质量语义检索的长期基线。

最重要的约束是维度一致：`EMBEDDING_DIM`、模型设置中的维度和模型真实输出必须相同。维度不匹配会导致索引失败、检索不到结果或把不兼容向量隔离。

更换 embedding 模型、供应商或维度时按以下流程执行：

1. 记录旧模型、旧维度和当前知识库的业务范围。
2. 添加并用小样本文档验证新 embedding 模型。
3. 修改相关模型或部署设置。
4. 在管理员后台触发受影响知识库的向量重建。
5. 对旧内容和新上传内容分别做检索验收，确认全部索引完成后再下线旧模型。

不要在重建期间删除唯一的原始文件或备份。向量可以重建，原始文档和元数据丢失后通常无法准确恢复。

## 个人版与完整版的向量后端

| 部署 | 向量位置 | 运维影响 |
| --- | --- | --- |
| 个人版 | SQLite 数据库中的内嵌向量 | `aivory.db` 和文件都在 `DATA_DIR`；单实例，不能放网络文件系统 |
| 完整版 | Qdrant 数据卷 | Qdrant 与 PostgreSQL、文件应作为一致备份单元保护 |

个人版已经具备向量检索，不需要为了 RAG 额外部署 Qdrant。完整版默认使用内部 Qdrant，除非有明确的外部服务设计，否则不要公开其端口或让应用连接到不受控的实例。

`VECTOR_BACKEND` 属于部署级拓扑配置。官方个人版固定为 SQLite 向量，官方完整版固定为 Qdrant；仅在自定义部署并理解后果时修改它。详见[环境变量](/docs/deployment/environment)。

## 文档解析与 OCR

普通文本、Office 文件、表格和带文字层的 PDF 可以通过本地解析链路处理。扫描件、图片型 PDF、复杂排版或高质量 OCR 场景通常需要 MinerU 等外部解析服务。

配置 MinerU 时，填写可从应用访问的 API 地址和密钥，并先用一份非敏感的扫描 PDF 验证。没有配置时，不应期待图片和扫描件自动产生高质量文字；系统可能只保存占位内容或有限提取结果。

解析失败的排查顺序：

1. 确认文件没有损坏、没有超出上传限制，也不是受密码保护或不可读格式。
2. 检查对应解析服务的网络、鉴权、额度和超时。
3. 确认对象存储地址可被解析服务访问。某些外部解析流程需要可下载的对象 URL。
4. 查看文档任务错误、应用日志和服务商返回，确定是解析、embedding 还是向量写入失败。

不要为了让 OCR 成功而将私有桶、内部文件服务器或数据库直接开放到公网。

## 存储与上传策略

“存储与上传”页面管理应用对象的存放方式、上传限制和保留边界。默认本地存储适合单机：头像等对象写入本地对象目录，用户上传和产物位于应用数据目录。它简单、可备份，但不适合多个应用副本同时共享。

需要多副本、跨节点或与外部解析服务协作时，使用受控对象存储并遵循最小权限：

- 使用单独的 bucket/prefix，不与其他业务共享管理员凭据。
- 只授予必要的读、写、列举或预签名权限，避免全账号管理员密钥。
- 设定生命周期、版本控制、加密、区域和访问日志策略。
- 将对象存储的凭据和配置视为敏感信息；后台配置导出可能包含它们。
- 先测试上传、下载、缩略图、解析、分享快照和删除，再迁移真实用户文件。

上传上限、单文件大小、总配额与管理员图标/技能资产限制共同影响用户体验。提高限制前要同步评估反向代理的请求体上限、磁盘/对象存储成本、解析内存和备份体积。

## 权限、工作区与分享

知识库不是全局公开搜索。管理员应结合用户、用户组和工作区检查谁可以上传、查看、检索、编辑或删除文档。

- 将不同客户、团队或数据分类放进不同知识库和工作区。
- 默认使用只读共享；仅给确实负责资料维护的人编辑或上传权限。
- 分享对话前检查引用片段、附件、预览图和工具产物是否会被带入只读快照。
- 用户删除、工作区移除或权限变更后，验证旧会话和旧知识库不会继续暴露不该访问的内容。

管理端的“文档与知识”“内容资源”“文件”页面适合排查状态、清理孤立资源和处理用户反馈。删除前先确认备份和保留策略，因为向量、原文件和产物的删除范围并不总是一致。

## 备份与恢复

备份必须同时覆盖关系数据、向量和原始文件。个人版重点是整个 `DATA_DIR`；完整版重点是 PostgreSQL、Qdrant、Redis、沙盒归档卷和 `DATA_DIR` 的一致性。

后台完整备份可用于迁移和恢复，但恢复前应先停止写入、保存现有数据副本，并在隔离环境验证。恢复后检查管理员配置、附件、知识库状态、向量检索和对象存储访问。详细流程见[升级、备份与恢复](/docs/deployment/upgrade-backup)。
